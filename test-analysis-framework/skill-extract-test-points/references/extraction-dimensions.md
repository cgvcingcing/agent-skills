# 测试点提取维度定义

本文档详细定义测试点提炼的 8 个维度，每个维度包含分类标准和识别方法。

---

## 维度 1：功能维度

按业务功能的重要性和使用频率分类。

### 分类标准

| 类别 | 定义 | 判断标准 | 优先级 |
|------|------|---------|--------|
| **主流程** | 核心业务的正向完整流程 | 最常见的成功路径，影响业务闭环 | P0 |
| **核心功能** | 关键业务能力验证 | 直接支撑业务目标的功能 | P0-P1 |
| **交互功能** | 模块间联动、数据传递 | 涉及多个模块协作的功能 | P1 |
| **常用功能** | 高频操作场景 | 用户日常使用频率高的功能 | P1-P2 |
| **辅助功能** | 帮助、设置、通知等 | 支持性功能，不影响主流程 | P2 |
| **管理功能** | 后台配置、权限管理 | 管理员操作的功能 | P1-P2 |

### 识别关键词

- 主流程：`主流程`、`核心路径`、`基本流`、`关键步骤`
- 核心功能：`核心`、`关键`、`必须`、`主要`
- 交互功能：`联动`、`触发`、`关联`、`同步`、`通知`
- 常用功能：`常用`、`高频`、`经常`
- 辅助功能：`辅助`、`帮助`、`提示`、`说明`
- 管理功能：`管理`、`配置`、`权限`、`后台`

### 提取示例

**需求原文**：
> 用户点击"立即购买"按钮后，系统跳转到订单确认页，显示商品信息、收货地址和支付方式。用户确认后点击"提交订单"，系统创建订单并跳转支付页面。

**提取结果**：
- 主流程：用户下单购买商品的完整流程
- 核心功能：创建订单、跳转支付
- 交互功能：商品信息传递、地址选择联动

## 维度 2：层次维度

按技术架构层次分类，适合前后端分离、微服务架构的项目。

### 分类标准

| 类别 | 定义 | 测试关注点 | 测试方法 |
|------|------|-----------|---------|
| **UI 层** | 界面展示、交互反馈 | 样式、布局、交互逻辑、视觉反馈 | 手工测试、UI 自动化 |
| **接口层** | API 调用、参数校验 | 接口协议、参数格式、返回结果 | 接口测试、契约测试 |
| **业务逻辑层** | 规则计算、流程控制 | 业务规则准确性、状态流转 | 单元测试、集成测试 |
| **数据层** | 数据库操作、数据一致性 | 数据存储、查询性能、事务 | 数据库测试 |
| **集成层** | 第三方服务、外部依赖 | 接口调用、异常处理、降级 | 集成测试、Mock 测试 |

### 识别方法

- UI 层：需求中提到`页面`、`按钮`、`输入框`、`显示`、`展示`
- 接口层：需求中提到`接口`、`API`、`请求`、`返回`、`调用`
- 业务逻辑层：需求中提到`计算`、`判断`、`规则`、`流程`、`条件`
- 数据层：需求中提到`存储`、`查询`、`数据库`、`表`、`字段`
- 集成层：需求中提到`第三方`、`外部`、`对接`、`同步`

### 提取示例

**需求原文**：
> 用户提交订单时，前端调用 Node 聚合接口 `POST /order/create`，Node 再调用订单服务 `POST /v6/order/create` 创建订单记录，同时调用库存服务 `PUT /v6/inventory/deduct` 扣减库存。

**提取结果**：
- UI 层：提交订单按钮点击
- 接口层：`POST /order/create`、`POST /v6/order/create`、`PUT /v6/inventory/deduct`
- 业务逻辑层：订单创建逻辑、库存扣减逻辑
- 数据层：订单表插入、库存表更新
- 集成层：Node 聚合层与服务端的调用关系

## 维度 3：类型维度

按测试类型分类，覆盖功能性和非功能性需求。

### 分类标准

| 类别 | 定义 | 测试内容 | 优先级 |
|------|------|---------|--------|
| **功能性** | 业务功能正确性 | 功能实现、逻辑准确性、数据正确性 | P0-P1 |
| **非功能性** | 性能、可用性、可靠性 | 响应时间、并发、稳定性 | P1-P2 |
| **兼容性** | 浏览器、设备、系统 | 跨平台、跨浏览器、分辨率适配 | P2 |
| **安全性** | 权限、注入、加密 | 权限校验、XSS、SQL 注入、数据加密 | P0-P1 |
| **易用性** | 用户体验、操作便捷性 | 交互流畅性、提示友好性、操作简便 | P2-P3 |

### 识别关键词

- 功能性：`功能`、`实现`、`完成`、`处理`
- 非功能性：`性能`、`速度`、`并发`、`稳定`、`可用性`
- 兼容性：`兼容`、`适配`、`浏览器`、`设备`、`系统`
- 安全性：`权限`、`安全`、`加密`、`验证`、`防护`
- 易用性：`易用`、`友好`、`简单`、`便捷`、`体验`

### 提取示例

**需求原文**：
> 订单列表页面需要在 2 秒内加载完成，支持 Chrome、Safari、Firefox 浏览器，仅管理员和订单负责人可以查看，密码传输必须加密。

**提取结果**：
- 功能性：订单列表查询和展示
- 非功能性：加载时间 < 2s
- 兼容性：Chrome/Safari/Firefox
- 安全性：权限控制（管理员、订单负责人），密码加密传输
- 易用性：（未明确提及，可推断：列表展示清晰、操作便捷）

## 维度 4：优先级维度

按缺陷影响程度分类，用于测试资源分配和执行顺序。

### 分类标准

| 级别 | 定义 | 判断标准 | 测试时机 |
|------|------|---------|---------|
| **P0 核心** | 阻塞性，影响主流程 | 主流程无法完成、数据丢失、系统崩溃 | 冒烟测试、每次构建 |
| **P1 主要** | 严重，影响核心功能 | 核心功能异常、大量用户受影响 | 核心回归、每日测试 |
| **P2 次要** | 一般，影响辅助功能 | 辅助功能缺陷、部分用户受影响 | 全量回归、提测前 |
| **P3 边缘** | 轻微，极端场景 | 边缘场景、极少用户、UI 优化 | 全量回归、发版前 |

### 判断流程

```
是否影响主流程？
    ↓ 是
  P0 核心
    ↓ 否
是否影响核心功能？
    ↓ 是
  P1 主要
    ↓ 否
是否影响常用功能？
    ↓ 是
  P2 次要
    ↓ 否
  P3 边缘
```

### 提取示例

**需求原文**：
> 1. 用户登录功能必须正常
> 2. 登录后显示用户头像
> 3. 支持记住密码功能
> 4. 登录页面支持夜间模式

**提取结果**：
- P0：用户登录功能正常（主流程）
- P1：登录后显示用户头像（核心功能）
- P2：记住密码功能（常用功能）
- P3：夜间模式（易用性优化）

## 维度 5：生命周期维度（CRUD+）

按数据操作类型分类，适合增删改查类的业务系统。

### 分类标准

| 类别 | 定义 | 测试关注点 | 常见业务场景 |
|------|------|-----------|-------------|
| **新增（Create）** | 创建数据 | 必填校验、格式校验、重复校验 | 注册、下单、新建 |
| **查询（Read）** | 检索数据、列表展示 | 查询结果准确性、分页、筛选、排序 | 列表页、详情页、搜索 |
| **修改（Update）** | 更新数据 | 权限校验、数据回显、并发修改 | 编辑、更新、设置 |
| **删除（Delete）** | 移除数据 | 二次确认、权限校验、关联数据处理 | 删除、取消、移除 |
| **导入（Import）** | 批量导入 | 模板校验、数据格式、错误提示 | Excel 导入、批量创建 |
| **导出（Export）** | 批量导出 | 数据一致性、文件格式、大数据量 | Excel 导出、报表下载 |
| **审核（Approve）** | 审批流程 | 状态流转、权限控制、通知 | 审批、审核、驳回 |

### 识别关键词

- 新增：`创建`、`新增`、`添加`、`注册`、`提交`
- 查询：`查询`、`搜索`、`列表`、`详情`、`查看`
- 修改：`修改`、`更新`、`编辑`、`保存`
- 删除：`删除`、`移除`、`取消`、`清除`
- 导入：`导入`、`上传`、`批量添加`
- 导出：`导出`、`下载`、`导出报表`
- 审核：`审核`、`审批`、`通过`、`驳回`

## 维度 6：场景维度

按业务场景的正常性分类，覆盖正常、边界、异常、极端场景。

### 分类标准

| 类别 | 定义 | 测试数据特征 | 优先级 |
|------|------|-------------|--------|
| **正常场景** | 符合预期的标准流程 | 有效数据、标准操作 | P0-P1 |
| **边界场景** | 临界值、极限条件 | 最大值、最小值、边界值 | P1 |
| **异常场景** | 错误输入、异常状态 | 无效数据、错误操作 | P1-P2 |
| **极端场景** | 并发、大数据量、弱网 | 高并发、大批量、网络异常 | P2-P3 |

### 提取示例

**需求原文**：
> 用户名长度为 3-20 位，支持字母和数字。

**提取结果**：
- 正常场景：输入 10 位字母数字组合
- 边界场景：输入 3 位（最小）、20 位（最大）、2 位（最小-1）、21 位（最大+1）
- 异常场景：输入特殊字符、中文、空值
- 极端场景：输入 1000 位超长字符串

## 维度 7：用户角色维度

按不同用户角色分类，适合多角色权限的系统。

### 分类标准

| 角色 | 定义 | 测试关注点 |
|------|------|-----------|
| **普通用户** | 基础权限 | 基本功能可用、权限限制正确 |
| **VIP 用户** | 增强权限 | 特权功能可用、与普通用户差异 |
| **管理员** | 完整权限 | 管理功能可用、操作日志记录 |
| **游客** | 未登录状态 | 公开内容可见、操作被拦截 |
| **其他角色** | 业务自定义 | 按业务规则验证 |

## 维度 8：时间维度

按使用时间和状态分类，关注时间相关的业务逻辑。

### 分类标准

| 类别 | 定义 | 测试关注点 |
|------|------|-----------|
| **首次使用** | 新用户场景 | 引导流程、初始化数据 |
| **日常使用** | 常规操作 | 正常业务流程 |
| **过期场景** | token 过期、数据过期 | 过期提示、重新登录 |
| **高峰场景** | 流量高峰期 | 性能、限流、降级 |

## 综合应用示例

**需求原文**：
> 管理员在订单管理页面可以查看所有订单，支持按状态筛选，点击订单可查看详情。普通用户只能查看自己的订单。

**8 维度分析**：

| 维度 | 分类结果 |
|------|---------|
| 功能维度 | 核心功能（订单查询） |
| 层次维度 | UI 层（页面）+ 接口层（查询接口）+ 数据层（订单表） |
| 类型维度 | 功能性（查询）+ 安全性（权限） |
| 优先级维度 | P0（核心查询功能） |
| 生命周期维度 | 查询（Read） |
| 场景维度 | 正常场景（有订单）+ 边界场景（无订单、大量订单） |
| 用户角色维度 | 管理员（全部）+ 普通用户（自己的） |
| 时间维度 | 日常使用 |

**提取测试点**：
- TP-001：管理员查看所有订单列表（功能/接口/功能性/P0/查询/正常/管理员/日常）
- TP-002：普通用户只能查看自己的订单（功能/接口/安全性/P0/查询/正常/普通用户/日常）
- TP-003：按状态筛选订单（功能/UI/功能性/P1/查询/正常/管理员/日常）
- TP-004：无订单时显示空状态（功能/UI/功能性/P2/查询/边界/管理员/日常）
- TP-005：点击订单查看详情（功能/UI/功能性/P1/查询/正常/管理员/日常）

## 维度选择建议

不是所有维度都必须应用，根据需求特点选择：

| 需求类型 | 推荐维度 |
|---------|---------|
| 简单 CRUD | 功能 + 生命周期 + 场景 + 优先级 |
| 多角色权限系统 | 功能 + 角色 + 安全性 + 优先级 |
| 前后端分离 | 功能 + 层次 + 类型 + 优先级 |
| 性能敏感系统 | 功能 + 类型 + 场景 + 优先级 |
| 电商/交易系统 | 全部 8 维度 |
