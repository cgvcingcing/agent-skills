# 测试用例生成技能

从测试点清单生成专业的 XMind 思维导图测试用例。

## Codex 执行约定

- 这个目录就是 skill 根目录。脚本和参考文档从本目录解析；输入、临时 JSON、覆盖率报告和 XMind 输出从项目工作区解析。
- 默认工作区为当前项目的 `workspace/`。调用脚本时传入实际文件路径，不要把带引号的 glob 当成文件名。
- 先读取 `references/case-writing-standards.md` 和 `references/priority-rules.md`，需要选择设计方法时再读取 `references/test-design-methods.md`。
- JSON 字段和输入包装格式以 `references/test-case-schema.md` 为准。
- XMind 生成器接受 JSON 数组，也接受 `{ "test_cases": [...] }` 包装对象；统一使用 `--input`、`--title` 和 `--output` 参数。
- 生成后检查 ZIP、`content.xml` 和追溯节点；只有输出文件存在且校验通过才报告完成。

## 核心能力

- **双输入模式**：支持读取测试点清单（来自测试点提炼技能）或直接读取需求文档
- **18 种测试设计方法**：不局限于传统 4 种，全面覆盖各种测试场景
- **智能方法匹配**：根据测试点特征自动选择最适合的设计方法
- **完整追溯关系**：需求 ID → 测试点 ID → 用例 ID 三级追溯
- **XMind 输出**：思维导图格式，层级清晰，易于评审和管理

## 18 种测试设计方法

### 经典黑盒方法（8 种）

| 方法 | 英文名 | 适用场景 | 触发条件 |
|------|--------|---------|---------|
| **1. 等价类划分** | Equivalence Partitioning (EP) | 有输入范围、格式要求 | 输入字段、参数、枚举值 |
| **2. 边界值分析** | Boundary Value Analysis (BVA) | 有数值/长度边界 | 最大值、最小值、范围限制 |
| **3. 判定表** | Decision Table (DT) | 多条件组合决定结果 | 复杂业务规则、多条件判断 |
| **4. 因果图** | Cause-Effect Graphing (CEG) | 输入与输出的因果关系 | 输入组合影响输出 |
| **5. 状态迁移** | State Transition Testing (STT) | 有明确生命周期 | 状态流转、工作流 |
| **6. 场景法** | Scenario Testing (ST) | 多步骤业务流程 | 端到端流程、用户故事 |
| **7. 正交试验** | Orthogonal Array Testing (OAT) | 大量参数组合 | 多因素、多水平组合 |
| **8. 错误推测** | Error Guessing (EG) | 经验驱动补充 | 高风险模块、历史缺陷多 |

### 扩展方法（10 种）

| 方法 | 英文名 | 适用场景 | 触发条件 |
|------|--------|---------|---------|
| **9. 用例组合** | Pairwise Testing | 参数两两组合 | 配置测试、兼容性测试 |
| **10. 流程分析** | Flow Analysis | 复杂业务流程 | 多分支、多路径流程 |
| **11. 分类树** | Classification Tree Method (CTM) | 层级分类输入 | 树形结构的输入分类 |
| **12. 探索性测试** | Exploratory Testing | 需求不明确 | 新功能探索、灵活测试 |
| **13. 基于风险** | Risk-Based Testing (RBT) | 资源有限 | 高风险优先测试 |
| **14. 基于模型** | Model-Based Testing (MBT) | 有形式化模型 | 状态机、流程图模型 |
| **15. 接口测试** | API Testing Design | 接口层测试 | API、接口调用 |
| **16. 性能测试** | Performance Testing Design | 性能需求 | 响应时间、并发、吞吐量 |
| **17. 安全测试** | Security Testing Design | 安全需求 | 权限、注入、加密 |
| **18. 兼容性测试** | Compatibility Testing Design | 多平台/浏览器 | 跨平台、跨浏览器 |

## 工作流程

### 阶段 0：输入源确认（新增）

**触发条件**：用户说"测试用例"或"生成测试用例"，但未明确指定输入源。

**交互逻辑**：
```
用户：测试用例

Codex：
检测到生成测试用例请求，请选择输入源：

1. 从测试点清单生成（推荐）
   - 使用测试点提炼技能已生成的测试点
   - 完整追溯关系
   - 设计方法已推荐

2. 从需求文档直接生成
   - 跳过测试点提炼阶段
   - 直接从需求生成用例
   - 适合快速生成场景

请输入选项编号 (1/2):
```

**自动判断**：
- 如果用户明确说"从测试点生成用例"或"根据测试点生成测试用例" → 直接进入模式 A
- 如果用户明确说"从需求生成用例"或"根据 XXX.png 生成用例" → 直接进入模式 B
- 如果用户只说"测试用例"或"生成测试用例" → 触发交互询问

### 阶段 1：输入识别与解析

**模式 A：从测试点清单生成**（推荐）
```
输入：workspace/output/test-points/test-points-*.md
解析：
  1. 读取 Markdown 文件
  2. 提取嵌入的 JSON 数据块
  3. 加载测试点列表
  4. 读取 suggested_methods
  5. 保留追溯关系（requirement_id, test_point_id）
```

**模式 B：从需求文档生成**（独立使用）
```
输入：workspace/input/requirements/*.md 或 *.png
解析：
  1. 读取需求文档
  2. 执行类似测试点提炼技能的需求解析
  3. 自动提取测试点
  4. 应用测试设计方法
```

### 阶段 2：测试设计方法应用

**智能方法匹配**：
```python
def select_methods(test_point):
    methods = []
    
    # 基于测试点特征自动匹配
    if has_input_constraint(test_point):
        methods.append('EP')  # 等价类
    
    if has_boundary(test_point):
        methods.append('BVA')  # 边界值
    
    if has_multi_steps(test_point):
        methods.append('ST')  # 场景法
    
    if has_multiple_conditions(test_point):
        methods.append('DT')  # 判定表
    
    if has_state_transition(test_point):
        methods.append('STT')  # 状态迁移
    
    if is_high_risk(test_point):
        methods.append('EG')  # 错误推测
    
    return methods
```

**方法组合策略**：
- 一个测试点可能应用多种方法
- 不同方法生成的用例去重合并
- 优先使用测试点中的 `suggested_methods`

### 阶段 3：用例生成

**用例编写规范**：

| 字段 | 规范 | 示例 |
|------|------|------|
| **用例标题** | 动作 + 对象 + 条件/场景 | "系统汇总表展示【系统】标签" |
| **优先级** | P0/P1/P2/P3 | P0 |
| **前置条件** | 明确的环境/状态准备 | "用户已登录，列表中存在系统汇总表" |
| **操作步骤** | 每步一个原子操作，编号 | "1. 打开汇总表列表页" |
| **预期结果** | 可验证的具体结果，编号对应步骤 | "1. 页面正常加载" |
| **测试点ID** | 追溯到测试点 | "TP-001" |
| **需求ID** | 追溯到需求 | "REQ-001" |
| **设计方法** | 使用的测试方法 | "EP+BVA" |
| **标签** | 适用端、功能模块 | "PC, 列表" |

**步骤编号规则**：
- 操作步骤：`1. 操作内容`
- 预期结果：`1. 预期内容`（编号与操作对应）
- 步骤与预期数组长度必须相等

**禁止的写法**：
- ❌ 模糊词：正常、正确、成功
- ❌ 多动作合并：输入用户名并点击登录
- ❌ 步骤中验证：验证、检查、确认
- ❌ 模糊预期：系统正常处理

**正确的写法**：
- ✅ 具体动作：输入账号"test@example.com"
- ✅ 可验证结果：显示"登录成功"提示，跳转到首页
- ✅ 分步操作：1. 输入账号  2. 点击登录

### 阶段 4：质量检查

**覆盖率验证**：
```
□ 测试点覆盖率 = 100%（如果输入是测试点清单）
□ 需求覆盖率 ≥ 95%
□ 每个测试点至少生成 1 条用例
□ 关键测试点（P0）生成 2-3 条用例（正常+异常）
```

**优先级分布观察**（不作为硬性门槛）：
```
□ 优先级与需求影响、风险依据一致
□ 小需求允许出现偏斜分布，并记录原因
```

**去重检查**：
```
□ 无语义重复用例
□ 不同设计方法产生的相似用例已合并
□ 只有前置条件、数据分区、操作和预期都等价时才合并
```

**可执行性验证**：
```
□ 每条用例的步骤明确可操作
□ 预期结果可验证
□ 前置条件明确
□ 无逻辑矛盾
```

### 阶段 5：XMind 生成

**思维导图结构**：
```
项目根节点（需求名称）
  └── 功能模块1
        └── 功能模块2（最多8层）
              ├── tc-p0: 用例标题（P0优先级）
              │     ├── tp: TP-001（测试点ID）
              │     ├── req: REQ-001（需求ID）
              │     ├── method: EP+BVA（设计方法）
              │     ├── pc: 前置条件
              │     ├── 1. 操作步骤1
              │     │     └── 1. 预期结果1
              │     ├── 2. 操作步骤2
              │     │     └── 2. 预期结果2
              │     └── tag: PC, 列表
              │
              └── tc-p1: 用例标题（P1优先级）
                    └── ...
```

**节点前缀规则**：
- P0 用例：`tc-p0: 用例标题`
- P1 用例：`tc-p1: 用例标题`
- P2 用例：`tc-p2: 用例标题`
- P3 用例：`tc-p3: 用例标题`
- 无优先级：`tc: 用例标题`

**输出位置**：
```
workspace/output/test-cases/test-cases-[需求名称]-[时间戳].xmind
```

## 质量标准

- ✅ 测试点覆盖率 = 100%（如果输入是测试点清单）
- ✅ 需求覆盖率 ≥ 95%
- ✅ 无冗余重复用例
- ✅ 优先级有风险依据
- ✅ 用例可执行性 = 100%
- ✅ 完整的三级追溯（需求→测试点→用例）
- ✅ 所有用例标记设计方法

## 约束

### 质量底线
- **测试点覆盖**：所有测试点必须生成用例
- **方法标记**：所有用例必须标记设计方法
- **追溯完整**：需求 ID、测试点 ID 不得缺失
- **优先级合理**：与影响和风险相符，比例仅作观察
- **无编造**：不凭空创造测试点中不存在的场景
- **无冗余**：相同验证目标的用例必须合并

### 用例编写约束
- 标题不使用"正常"、"正确"等模糊词
- 步骤不合并多个动作
- 步骤不包含"验证"、"检查"等验证动词
- 预期结果必须具体可验证
- 步骤与预期编号一一对应

### 输出约束
- 文件名格式：`test-cases-[需求名称]-[14位时间戳].xmind`
- 时间戳格式：`YYYYmmddHHMMSS`
- 模块层级不超过 8 层
- 必须输出到 `workspace/output/test-cases/` 目录

## 脚本调用

### 生成 XMind
```bash
TIMESTAMP=$(date +%Y%m%d%H%M%S)
python3 "<skill-root>/scripts/xmind_generator.py" \
  --input "<workspace>/tmp/cases_${TIMESTAMP}.json" \
  --title "新人三单样式调整" \
  --output "<workspace>/output/test-cases/test-cases-新人三单-${TIMESTAMP}.xmind"
```

### 覆盖率分析
```bash
python3 "<skill-root>/scripts/coverage_analyzer.py" \
  --testpoints "<workspace>/output/test-points/test-points-*.md" \
  --testcases "<workspace>/tmp/cases_*.json" \
  --output "<workspace>/tmp/coverage_report.json"
```
